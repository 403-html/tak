# Packed raster row prediction

RFC 0039 added three fixed row strides to the RFC 0038 width search.
The complete Calgary total fell from 893,989 to 892,381 bytes,
a reduction of 1,608 bytes or 0.180%. All 126 trial artifacts
restored exactly. The SHA-256 digests of all 72 control artifacts
match the corresponding RFC 0038 results.

| Profile | Complete bytes | Search encode s | Search MB/s | Search peak KiB | Selected decode s | Selected decode MB/s | Selected decode peak KiB |
|---|---:|---:|---:|---:|---:|---:|---:|
| RFC 0038 control | 893,989 | 30.636 | 0.106 | 122,800 | 3.240 | 1.004 | 48,672 |
| Extended search | 892,381 | 56.465 | 0.058 | 151,392 | 3.294 | 0.987 | 48,672 |

Search time sums every encode. Throughput uses the original
3,251,493 bytes once. Decode time sums the selected runs.
The screen includes process launch and file output. Byte comparison
occurred outside timing. Each measurement is a single run.

The sole gain is on pic. Its artifact falls from 51,986 to 50,378
bytes with stride 216. Strides 256 and 304 increase its size to
87,154 and 76,748 bytes. Obj2 selects ordinary TK32 at 76,959 bytes.
These results support the chosen stride on pic. The experiment
provides no held-out evidence for the row predictor.

The screen misses the pre-set 0.25% gate by 627 bytes. The candidate
is 6,521 bytes above xz -9 on Calgary. The retained RFC 0038
screen remains 8,129 bytes above xz -9. No new enwik9 artifact was
tested. The retained 243,396,020-byte enwik9 artifact is
27,721,824 bytes above xz -9 and 46,396,020 above nominal M2.

## Reproduction

```console
cargo build --release -p tak-tensor --bin tak-lz-stream
python3 benchmarks/runners/byte_shuffle.py screen target/release/tak-lz-stream CALGARY --row-xor
```

Use every independent file in the [Calgary manifest](../../benchmarks/reports/raw/2026-11-22-calgary-inputs.tsv).
The raw `width` column stores 0 for identity, 2, 4, or 8 for byte
shuffle, and 216, 256, or 304 for row stride. The wrapper includes
its 10-byte header in every row-stride artifact. A post-screen check
reproduced the winning artifact digest and exercised rejection of
a truncated header, unsupported stride, damaged checksum, and
insufficient output limit.

Source is commit `aa4b3b1` plus RFC 0039. Linux 6.18.57, Intel Xeon
Platinum 8573C, x86-64, three visible logical CPUs, 10,207,480 KiB
visible RAM, and an 8 GiB cgroup limit. Rust 1.85.0 release build,
Python 3.12.14, and one codec thread.

The deferred held-out files came from the public libtiff
[pics-3.8.0 archive](https://download.osgeo.org/libtiff/pics-3.8.0.tar.gz),
SHA-256 `e0e34732b61e1ce49eff2c7a079994c856d2a5f772f5228c84678272bc6829a9`.
Pillow 13.0.0 exported the first frame in mode `1` with `tobytes()`.
The prepared rasters were never encoded.
