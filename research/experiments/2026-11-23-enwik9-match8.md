# Accepted enwik9 validation: bounded exact match

## Status

RFC 0009 reaches M1 on enwik9 with bounded memory and exact restoration. This
is a non-publishable single-sample validation without a warm-up. `TKM8` remains
a research artifact.

## Fixed model and accounting

The model is unchanged from Silesia development and Calgary validation: exact
8-byte suffix, divisor-4 bonus, 1,048,576 direct-mapped slots, fixed hash, and
collision replacement. The streaming encoder produces the same artifact bytes
as the buffered encoder in conformance tests.

The complete 28-byte header and arithmetic payload are counted. The process
uses one thread. Input size is exactly 1,000,000,000 bytes. Input SHA-256 is
`159b85351e5f76e60cbe32e04c677847a9ecba3adc79addab6f4c6c7aa3744bc`.

CPU was Intel Xeon Platinum 8573C with three visible logical CPUs. OS was Linux
6.18.57. Compiler was Rust 1.85.0 in release mode. Measurements were made on
2026-11-23 Europe/Warsaw from commit `ff75b1c` plus the streaming working tree.

Raw measurements are in
`benchmarks/reports/raw/2026-11-23-enwik9-match8.tsv`, SHA-256
`f9bc2d154f3987487fc8d5a6a9c391d500397c2db84f448e7358f0df564e0d36`.

## Decision

Accept M1. Keep RFC 0009 fixed as the new classical control. The next ratio
research must target information not already captured by last-continuation
matching. Speed work must address the arithmetic decoder and probability
lookup without changing artifact bytes.

Do not claim proximity to M2. Do not implement a tensor model unless a new RFC
defines how it represents match state and why it can beat this direct control.
